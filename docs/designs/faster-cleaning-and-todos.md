## Problem Statement

A 3-minute flight (11,032 frames) takes 503 s, about 8.4 minutes, on an RTX 4070 Ti (0.1.2,
measured 2026-10-28, 44.8 ms/frame steady). 0.1.2 made the wait watchable, but not much
shorter: of the four speed ideas measured, only the pinned upload (+1.1%, bit-identical)
survived. The owner wants it faster, and the TODO list cleared.

## Measurements behind this design (2026-10-29, `hdz_30s.mp4`, GPU clean step only)

A kernel profile over 40 frames found 37.2 ms of GPU work per frame. No single kernel
dominates:

| Where | ms/frame | What |
|---|---|---|
| RAFT update loop (6 iterations) | ~8.2 | ~1.37 ms per iteration; 4 iterations failed the gate |
| Convolutions | ~7.2 | the U-Net and RAFT's encoders |
| Unfused element-wise (≈85 add, 90 mul, 140 casts…) | ~6+ | fp32 maths in warp/blend/repair/upscale, one kernel per op |
| `cat`/`stack` + device-to-device memcpy | ~4.3 | neighbour planes stacked every frame (`Cleaner.align`), output packing, stats, copies into graph inputs |
| `avg_pool2d` (fp16, 9 calls) | 3.8 | 6 are LK refine's separable 5-px window (2 per iteration × 3); 3 are `ops.box_mean` |
| Bicubic upscale + grid_sample warps | ~2.2 | |
| Other (remaster stage, small kernels) | ~5.5 | remainder to 37.2 |

The host waits 28.5 ms/frame inside the one `bool()` sync: the GPU is the limit, as before.

## Root cause of the P1 boxes (verified 2026-10-29)

The measured OSD mask, drawn over output frame 0 of `hdz_30s.mp4`
(`docs/designs/evidence/osd-mask-overlay-hdz30s.png`, to be committed from the session
scratchpad beside `osd-boxes-hdz30s.png`), lines up exactly with the boxes on the propeller
guard and around the desk holes. Three steps produce it:
- `picture.detect_osd` counts anything still with an edge as OSD (`stable & edges`). On this
  clip that is 16.9% of the frame, mostly scenery, because the drone sits still on a desk.
- It then fills each component's whole bounding box (`filled[y:y+h, x:x+w] = 1`).
- The GPU pipeline switches hard at the mask: the noisy current frame inside, the fused
  frame outside.

The box edge is what shows. The mask has eight consumers, all in `gpu/pipeline.py` unless
noted: the final `torch.where` on y/u/v (l. 841-843), the U-Net's post-blend
(`model/infer.py` `_run`, `torch.where(osd, centre, out)`, not a network input, so no
retrain), `destripe` (l. 660), `derainbow` (l. 667), `keep` (destripe detail, overlay repair
l. 523), `keep_half` (`_repair_pixels` l. 560 and the OSD repair term l. 596), and the
remaster stage's `boxes` (`remaster/stage.py` l. 82).

## What makes this cool

The bit-identical wins are free: a faster app with nothing to judge. The gated wins come
with the tools 0.1.2 built (`tools/ab_speed.py`, `tools/gate.py`), so every change that
alters a pixel is measured against the current output and looked at. The box fix removes a
flaw the owner would catch on every landing and menu screen.

## Premises (auto-agreed under the owner's standing instruction)

1. Speed has to come from less GPU work per frame (the host waits 28.5 ms/frame on the GPU).
2. Bit-identical changes go first; they need no gate, only an identity test.
3. Any change to the output passes the relative gate and the owner's artifact hunt, or it
   doesn't ship.
4. The box fix changes the output, so it goes through the same gate, with "the boxes are
   gone" as an extra check.

## Approaches considered

- **A: bit-identical only.** S effort, low risk, a few % at most (see Wave 1's spike).
- **B: layered, chosen.** A first, then output-changing levers one at a time, each through
  the gate. M effort, medium risk, ~10-20% estimated (to be measured).
- **C: torch.compile / Triton fusion of the whole clean step, and TensorRT for the U-Net.**
  Possibly the largest gain, but both bring native runtimes into the PyInstaller installer,
  and TensorRT engines are built per GPU architecture. Deferred (TODOS.md) and reopened as its
  own design if B lands below the 20% goal.

## Recommended approach: B

```
 Wave 1 (identity)      Wave 3 (box fix, gated)     Wave 2 (levers, gated one at a time)
 spike -> 1a/1b  --->   mask + soft alpha   --->    LK box filter -> fp16 warp/blend
 framemd5 = 0.1.2       gate vs Wave-1 output       gate vs previous shipped output
        \_______________________ release 0.1.3 (Wave 1 + Wave 3 required) ____/
```

### Wave 1: bit-identical speed (ships if identical and the `ab_speed.py` median is ≥2% faster; below 2% it is dropped as not worth the code)
1. **Spike first (≤1 h):** measure how much of the 4.3 ms of cat/stack/memcpy is
   `Cleaner.align`'s five `torch.stack` calls (y, u, v, yb, noise over 6 slots) versus output
   packing (l. 721/737), stats (l. 474) and `_Graph` input copies. Only the align stacks and
   graph copies are Wave 1's target.
2. **1a, persistent neighbour buffers, if the spike shows ≥1 ms:** the window order must stay
   exactly today's (`idx = [min(i, n-1) …]`, oldest to newest, the last neighbour repeated
   short of a full window), because every reduction over the slot axis (weighted blends,
   `trimmed_mean`, `amin`, the repair sums) sums in slot order and a different order changes
   float results. The buffers are filled in that logical order by an index tensor captured
   once per window shape; the edge cases (clip start and end, each `--cut` range, a run after
   Stop or failure) take today's `torch.stack` path, and the buffers are reset per clip. If
   identity cannot be kept, 1a moves to Wave 2 as a gated lever.
3. **1b, graph inputs without copies:** producers write straight into `_Graph.inputs`. All
   producers and replays run on the current stream (the pinned upload already waits on its
   event before the clean step), so a slot is not overwritten until the replay that reads it
   has been enqueued after it in stream order. No cross-stream writes are allowed.
4. **Proof:** framemd5 identity on `hdz_30s.mp4` and the synthetic suite (Classic and
   Learned, with breakup), run twice to catch a race; unchanged repair counts; `ab_speed.py`
   medians of 3.

### Wave 3: the box fix (output-changing, gated), before Wave 2
5. **OSD mask (`picture.detect_osd`):** the mask is
   - glyph pixels (`glyph_mask`: bright strokes with a dark outline, present in ≥ the
     configured share of frames), dilated by 3 px so the outline and halo are inside;
   - plus still-with-edges pixels (`stable & edges`) only within connected components that
     contain at least `min_overlay_pixels` glyph pixels, also dilated by 3 px;
   - no bounding-box fill anywhere.
   Analog OSD chips (MAX7456/AT7456) and the digital systems draw every element (numbers,
   icons, crosshair, horizon) from an outlined font, so non-text graphics are glyphs too.
   Elements that move (horizon while rolling) are not in today's mask either; no change there.
6. **Soft alpha, built once:** `Cleaner.__init__` turns the bool mask into a float `alpha`:
   1 on every mask pixel, falling to 0 over 4 px *outside* the mask (distance transform), so
   no OSD pixel is ever partly fused or graded. `alpha_half = area_half(alpha)` for u/v.
   `keep = 1 - alpha`, `keep_half = 1 - alpha_half` (both already floats, so `destripe`,
   `_repair_pixels` and the OSD repair term take it unchanged). The three `torch.where` calls
   at l. 841-843, `destripe`, `derainbow` and the U-Net post-blend become lerps by alpha. The
   remaster stage's `boxes` takes the same alpha.
7. **Proof:**
   - a hand-labelled OSD mask for `hdz_30s.mp4` frame 0 (committed under `tests/data/`):
     the new mask covers ≥98% of labelled pixels and adds ≤1.5× the labelled share;
   - the box edges are gone (evidence image redone beside the old one);
   - `test_osd`, `test_osd_layout`, `test_osd_truth` and
     `osd_pixels_are_not_graded_and_no_box_shows_around_them` pass;
   - new unit tests on synthetic frames: still scenery with edges and no glyphs gives an
     empty mask; a glyph gives its strokes plus 3 px; alpha is 1 inside and falls to 0 within
     4 px outside;
   - the relative gate (OSD-box metric and pulsing) passes against Wave 1's output;
   - the eye check covers menu, landing, still-on-desk and in-flight frames with the
     crosshair and horizon visible, on `hdz_30s.mp4` and the owner's named clip.

### Wave 2: output-changing speed, one lever per gate run
The gate baseline is re-cut after every shipped output change (after Wave 3, then after each
lever), so each run isolates one lever.
8. **LK box filter:** the 6 LK `avg_pool2d` calls (2 per iteration) become one grouped-conv
   5×5 box sum per iteration in fp16 (tensor cores accumulate in fp32), divided by a
   precomputed count map so the `count_include_pad=False` edge normalisation is unchanged.
   No fp16 cumsum: prefix sums over a row overflow fp16. Expected −1.5 to −2.5 ms.
9. **fp16 in warp/blend:** the warped neighbour planes (`grid_sample` output) and the blended
   y/u/v values become fp16. Blend weights, distance weights, alpha, flows and every
   accumulation (`.sum(0)`, totals, divisions) stay fp32.
10. **(Deferred) U-Net in TensorRT:** moved to Approach C in TODOS.md; same packaging risk.

### Small TODOs, folded in
11. `--cut` error text: an `ArgumentTypeError` saying
    "START-END in seconds or m:ss, e.g. 0-4.5 or 1:05-1:20".
12. Live caption total off by one: **closed, won't do.** The caption counts packets and the
    difference is one frame at most; the decoded count would cost an extra probe.
13. **Speed estimate calibrated to the GPU (E2):** after a run that completes with ≥600
    output frames, store `measured ÷ estimated fps` in QSettings under a key of
    (GPU name, app version, Learned/Classic), updated as an average with the previous value
    (½ old + ½ new) and clamped to 0.5-2.0. A new app version or GPU starts with no ratio.
    Stopped, failed and short runs never update it. "Reset to defaults" clears all ratios.
14. **Cleaned-frame card thumbnail (E3):** on done, the card shows the last live picture's
    "after". With no live picture (very short clip, none received), the card keeps today's
    thumbnail. A stopped or failed clip keeps today's thumbnail.
15. **5-second motion check (E6):** **closed, won't do.** The live view already shows motion a
    minute in, and Stop is under it.
16. **Play while it renders (E5):** stays deferred, as the largest item, until waves 1-3 ship.

## Outcome (built 2026-10-29, branch feat/faster-0.1.3)

- **Wave 1:** the spike found the align stacks at ~0.2 ms (1a dropped, under its 1 ms bar)
  and the repair graphs' input copies at 1.09 ms plus ~0.4 ms of output clones. Shipped: the
  fix graph reads the detect graph's own buffers and outputs, only the centre planes are
  copied out, and `_norm_grid` writes in place. framemd5 identical (Learned x3 each side,
  Classic x1), `hdz_30s.mp4` median 93.3 -> 91.2 s (+2.3%).
- **Wave 3, two masks:** `detect_osd` is now the OSD's strokes (any sample) and outline
  (4 px: 3 px covered 95% of the synthetic OSD, 4 px 98.6%), with no box. It drives only
  what is seen: a soft alpha (1 on the mask, 0 four px out) for the U-Net blend, destripe,
  derainbow, the Classic fusion's own exclusion and the remaster stage. The alpha is also
  gated per frame: an element keeps the plain frame only while a stroke of it shows within
  24 px somewhere in the cleaning window (without that, `hdz_30s.mp4`'s flight timer left
  "000"-shaped patches on the propeller guard during the menu; with the gate only on the
  centre frame, a damaged frame lost its readout). The old mask is kept unchanged as
  `detect_osd_regions` for everything never shown: breakup detection and its `valid` map,
  every repair step, the flow fill, the levels and the redraw's layout. With the new mask
  there, `dusk.mp4` frame 46 was repaired by rows instead of whole and lost its throttle
  readout; with the split, repair matches 0.1.2 row for row.
- **Gate (vs Wave 1's output): PASS, 19 of 19**, all 7 real clips; still pulsing
  1.733 -> 1.498, worst tiles 9.94 -> 6.22, OSD box 0.298 -> 0.267, outage frames
  18.728 -> 18.757. (An earlier version missed outage frames by 0.005 dB; the owner accepted
  that miss, "Ship it (recommended)", 2026-10-29, but the final version passes.)
- **Speed:** the per-frame OSD check first cost 22% (57x57 and 85x85 max-pools per frame),
  fixed with separable dilation (`ops.dilate`, identical result) and by the stage reusing
  the cleaner's alpha; it still costs ~1.6%. 0.1.3 vs 0.1.2: +0.4 to +0.7% (median of 3,
  `hdz_30s.mp4`). The 20% goal is now Wave 2's (TODOS.md).
- **Proof not done as planned:** no hand-labelled frame-0 mask (frame 0 is a menu, and the
  label needs a person). Coverage was measured instead: 98.6% of the synthetic OSD's true
  pixels, 99.5% of `hdz_30s.mp4`'s per-frame strokes. The owner's named eye-check clip is
  still open; `hdz_30s.mp4`, `dusk.mp4`, `night_street.mp4`, `playground.mp4` and
  `sunny.mp4` were eye-checked.
