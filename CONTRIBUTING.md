# Contributing to AnaHD

Thanks for helping. AnaHD is a small project kept by one person, so issues and pull
requests are read when there is time; a clear report gets looked at first.

## Reporting a problem

Open an issue with the **Something went wrong or looks wrong** template. The most useful
reports have:
- the AnaHD version, Windows version, graphics card and driver;
- the camera, VTX and goggles or DVR that made the recording (AnaHD's learned cleaning
  was trained on one setup, so this matters);
- the error text, or for "looks wrong" a before/after still from the results page.

Please don't attach whole flights. A few seconds, cut with AnaHD's cut markers, is plenty.
Security problems go through [SECURITY.md](SECURITY.md), not public issues.

## Suggesting a feature

Use the **Idea or request** template. Say what you want to do with your footage and what
gets in the way now; a short clip or still of the problem helps more than a proposed
design.

## Working on the code

You need Windows or Linux, [uv](https://docs.astral.sh/uv/), FFmpeg 6 or newer on PATH,
and for the full tests an NVIDIA GPU with CUDA 12.8 support.

```
git clone https://github.com/dominic-salas/AnaHD && cd AnaHD
uv sync --extra app
uv run anahd-app                 # the desktop app
uv run anahd flight.mp4          # the command line
```

Before opening a pull request, run the same checks as CI:

```
uv run ruff check .
uv run ruff format --check .
uv run mypy
uv run pytest                    # GPU tests skip without a GPU; run them if you can
uv run python scripts/third_party.py --check
```

A few tests compare against real DVR recordings, which are not in the repository. They
skip unless `ANAHD_DEV_CLIPS` points at a folder of clips (and, for the OSD tests,
`ANAHD_OSD_FONT` at a Betaflight `.mcm` font).

Guidelines:
- Keep a pull request to one change, and say what it fixes and how you checked it.
- Tests measure against the truth (the synthetic recordings in `tests/synthetic.py` have a
  known clean picture) or against a plain upscale, never against AnaHD's own earlier
  output. A change to the picture needs a test that would fail without it.
- Speed numbers need the GPU, the input size and whether start-up is included.
- Never commit recordings, rendered video or model weights. Test footage is generated by
  the tests.
- New dependencies need a licence compatible with shipping them in the installer; add them
  to `THIRD_PARTY_LICENSES.md` by running `scripts/third_party.py`.
- The app's look (near-black, thin borders, monospace uppercase labels, one red accent)
  should stay consistent: reuse the existing styles in `src/anahd/app/look.py`.
